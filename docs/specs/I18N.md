# Internationalization (i18n)

> Multi-language support in the Telegram Mini App and bot based on the user's `language_code`.

## Concept

Telegram provides `language_code` in `initData` (frontend) and in `Message.from` (bot) — the language is determined automatically without additional UX.

```
Telegram User → language_code: "ru" | "en" | ...
                      │                    │
               Frontend (React)       Bot (Java)
               react-i18next     Spring MessageSource
               locales/*.json    i18n/messages*.properties
```

- **Fallback**: `en` — for any unsupported language
- **Extension**: adding a new language = adding one file
- **No Redis storage** — language is taken from the Telegram context on each request

| Code | Language | Status |
|-----|------|--------|
| `en` | English | ✅ Fallback |
| `ru` | Russian | ✅ Primary |
| `ar` | Arabic | Locale files present; wiring pending |
| `de` | German | Locale files present; wiring pending |
| `es` | Spanish | Locale files present; wiring pending |
| `fr` | French | Locale files present; wiring pending |
| `uk` | Ukrainian | Locale files present (ISO 639-1 `uk`); wiring pending |
| `zh` / `zh-CN` | Simplified Chinese | Locale files present; wiring pending |

## Frontend: react-i18next

### Installation

```bash
npm install i18next react-i18next
```

### Files

```
frontend/src/i18n/
├── index.ts               # initialization
└── locales/
    ├── en.json            # source of truth
    └── ru.json
```

### Initialization (`src/i18n/index.ts`)

```typescript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import WebApp from '@twa-dev/sdk';
import en from './locales/en.json';
import ru from './locales/ru.json';

i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, ru: { translation: ru } },
  lng: WebApp.initDataUnsafe.user?.language_code ?? 'en',
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
});
export default i18n;
```

Import in `src/main.tsx` before render: `import './i18n';`

### Usage in components

```typescript
const { t } = useTranslation();
t('common.cancel')                              // → "Cancel" / "Отмена"
t('chat.messagePlaceholder', { name: 'Alice' }) // → "Message Alice..."
t('incomingRequest.errors.SESSION_NOT_FOUND')
```

## Backend/Bot: Spring MessageSource

### Files

```
backend/src/main/resources/i18n/
├── messages.properties      # fallback (= _en)
├── messages_en.properties
└── messages_ru.properties
```

Use `ReloadableResourceBundleMessageSource` with `setDefaultEncoding("UTF-8")` — then Cyrillic and emojis can be written directly, without `\uXXXX`.

### `I18nConfig.java`

```java
@Configuration
public class I18nConfig {
    @Bean
    public MessageSource messageSource() {
        var source = new ReloadableResourceBundleMessageSource();
        source.setBasename("classpath:i18n/messages");
        source.setDefaultEncoding("UTF-8");
        source.setFallbackToSystemLocale(false);
        return source;
    }
}
```

### `BotMessageService.java`

```java
@Service
@RequiredArgsConstructor
public class BotMessageService {
    private final MessageSource messageSource;

    public String get(String key, String languageCode, Object... args) {
        return messageSource.getMessage(key, args, key, resolveLocale(languageCode));
    }

    private Locale resolveLocale(String languageCode) {
        if (languageCode == null) return Locale.ENGLISH;
        return switch (languageCode) {
            case "ru" -> new Locale("ru");
            default   -> Locale.ENGLISH;
        };
    }
}
```

Get language in the bot: `update.getMessage().getFrom().getLanguageCode()`
