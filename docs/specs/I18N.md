# Internationalization (i18n)

> UI and bot strings from the user's `language_code` (Telegram) with English fallback

## Supported languages

| Code | Language | Frontend | Bot (`messages_*.properties`) |
|------|----------|----------|--------------------------------|
| `en` | English | ✅ | ✅ (fallback) |
| `ru` | Russian | ✅ | ✅ |
| `ar` | Arabic | ✅ | ✅ |
| `de` | German | ✅ | ✅ |
| `es` | Spanish | ✅ | ✅ |
| `fr` | French | ✅ | ✅ |
| `uk` | Ukrainian | ✅ | ✅ |
| `zh-CN` | Chinese (Simplified) | ✅ | ✅ (`messages_zh.properties`) |

Telegram `language_code` is normalized on startup (e.g. `zh`, `zh-hans` → `zh-CN`). Unsupported codes fall back to `en`.

User can override via Settings `LanguageSwitcher` or the first-run language picker (after auth, before the briefing). The picker is shown only when no saved pref exists — replay of onboarding steps does **not** reset language.

Persist (dual-write): `localStorage` key `preferred_language` (sync, used at i18n init **before** Telegram/`navigator` autodetect) **and** Telegram CloudStorage `preferred_language` (async override / cross-device). Server-side bot preference: Redis `lang:pref:{internalId}` (set via STOMP `/app/user.setLanguage`).

## Frontend

**Stack:** `i18next` + `react-i18next`

```
frontend/src/i18n/
├── index.ts          # init, SUPPORTED_LANGS, localStorage then Telegram/browser
├── languagePreference.ts  # read/write preferred_language, resolveInitialLanguage
├── useLanguagePrefReady.ts # gate: wait for CloudStorage after auth
└── locales/
    ├── en.json       # source of truth for key structure
    ├── ru.json
    └── … (ar, de, es, fr, uk, zh-CN)
```

Import in `main.tsx`: `import './i18n'`

```typescript
const { t } = useTranslation();
t('chat.messagePlaceholder', { name: 'Alice' });
t('incomingRequest.errors.SESSION_NOT_FOUND');
```

### Key namespaces (overview)

| Namespace | Screens |
|-----------|---------|
| `common`, `status` | Shared chrome, connection state |
| `home` | Search, session list |
| `chat` | DM composer, messages, actions, a11y |
| `burnDialog`, `incomingRequest`, `verification`, `handshake`, `pendingRequest` | DM lifecycle |
| `room.*` | Create/join/manage/chat/burn/leave |
| `wallet`, `staking`, `governance` | TON features |
| `joinLanding` | Web invite landing |
| `help.*` | In-app help sheets |

Full key list: `frontend/src/i18n/locales/en.json`.

## Backend / bot

```
backend/src/main/resources/i18n/
├── messages.properties      # English fallback
├── messages_en.properties
├── messages_ru.properties
└── messages_{ar,de,es,fr,uk,zh}.properties
```

`I18nConfig` → `ReloadableResourceBundleMessageSource` (UTF-8).

`BotMessageService`:

- `get(key, languageCode, args…)` — sync, from Telegram `language_code`
- `getForUser(key, telegramId, args…)` — reads Redis `lang:pref` first

Example keys: `bot.start.text`, `bot.help.text`, `bot.notify.chatRequest`, `bot.notify.newMessage`, `bot.cmd.start`.

## Adding a language

1. Copy `en.json` → `locales/{code}.json`; translate values
2. Add code to `SUPPORTED_LANGS` in `i18n/index.ts` and `resources` map
3. Copy `messages_en.properties` → `messages_{code}.properties`
4. Extend `BotMessageService.resolveLocale()` switch
5. Run `node scripts/i18n/check-i18n.mjs --strict` (or `npm run i18n:check` from `frontend/`)
6. For help copy: `node scripts/i18n/check-i18n.mjs --check-help`
