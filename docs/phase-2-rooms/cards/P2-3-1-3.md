## Описание

Redis: ключ `room_keys:{roomId}:{epoch}` — хранить зашифрованные ключи для участников как opaque blobs (по tgId или по ключу участника). Сервер не расшифровывает; только relay. RoomKeysRepository: putEncryptedKey(roomId, epoch, tgId, blob), getEncryptedKeys(roomId, epoch), deleteEpoch.

## Критерии приёмки

- [ ] Структура позволяет хранить для каждого участника его зашифрованную копию группового ключа (или один blob на участника).
- [ ] TTL или удаление при BURN_ROOM; при rekey — новый epoch.
- [ ] Backend только сохраняет/отдаёт по запросу авторизованному участнику его blob.

## Зависимости

- P2-1.1.2 (RoomRepository), P2-3.1.1 (протокол).

## Заметки

- Альтернатива: не хранить ключи на сервере, а доставлять key bundle только в момент JOIN_APPROVED через STOMP; тогда Redis для ключей не обязателен для MVP.
