## Описание

Исследовать протоколы группового E2EE (Signal Sender Keys, Tree-DH/MLS), выбрать подход для MVP комнат. Зафиксировать в docs краткий протокол: кто генерирует групповой ключ, как он доставляется новым участникам, как выполняется ротация при выходе.

## Критерии приёмки

- [ ] Документ в docs/ (например docs/phase-2-rooms/GROUP_KEY_PROTOCOL.md) с описанием выбранной схемы.
- [ ] Решение: один общий групповой ключ (проще) vs Sender Keys; обоснование для текущего размера комнаты (до ~50).
- [ ] Схема выдачи ключа новому участнику (encrypted key bundle от владельца/участников).

## Зависимости

- Нет.

## Заметки

- Для MVP допустимо: один симметричный групповой ключ, создаётся при создании комнаты; при добавлении участника владелец шифрует ключ его публичным ключом и отправляет; при выходе — rekey (новый групповой ключ, рассылка зашифрованных копий).
